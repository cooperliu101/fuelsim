# 纯传热单核性能比较

2026-09-19，在同一台 Intel Core i9-13980HX 机器上比较已通过精度验收的
三个 DC3D8（三维八节点独立传热单元）算例。每组先预热一次，再交替运行
Fuelsim 和 Abaqus 各三次。以下统计排除预热。

## 测量结果

完整运行时间从启动生产命令到进程成功退出，包含读网格、问题构造、求解、
必要诊断和退出。准备输入文件、Python/PowerShell 控制脚本启动及参考提取
均不计入。两个程序都关闭用户请求的场、历史和检查点输出；Abaqus 自身
必要的作业文件仍由程序生成。

| 算例 | Fuelsim 中位数（范围），秒 | Abaqus 中位数（范围），秒 | Abaqus/Fuelsim 时间比 |
|---|---:|---:|---:|
| 稳态导热 | 1.039（0.996—1.267） | 6.127（6.118—6.133） | 5.90 |
| 瞬态导热，20 步 | 8.561（8.483—8.690） | 14.155（14.153—14.170） | 1.65 |
| 多材料瞬态界面，20 步 | 10.014（9.939—10.059） | 16.169（16.167—16.215） | 1.61 |

这组测试中 Fuelsim 的完整运行时间较短，但不能把上表的比值直接解释成
矩阵求解速度。下表单独列出两个程序各自的内部计时中位数：

| 算例 | Fuelsim 求解流程，秒 | Abaqus 分析墙钟时间，秒 | Abaqus 分析 CPU 时间，秒 |
|---|---:|---:|---:|
| 稳态导热 | 0.479 | 1（范围 1—2） | 1.3 |
| 瞬态导热 | 7.980 | 10 | 9.5 |
| 瞬态界面 | 8.999 | 10 | 9.9 |

Fuelsim 使用生产输出 `total_seconds`，覆盖稳态加载或瞬态推进流程，
不包含前面的输入读取和问题构造；Abaqus 使用最后的 `JOB TIME SUMMARY`。
二者内部计时边界不同，且 Abaqus 墙钟记录仅有整数秒，因此不再从下表计算
精确的求解器加速比。Fuelsim 运行在 WSL/Linux，Abaqus 2025 运行在同一台
机器的 Windows；操作系统、进程启动和文件系统开销都属于本次环境差异。
两个环境分别固定逻辑处理器 0，不能据此保证虚拟处理器和宿主物理核一一对应。

## 相同的物理问题与规模

三个算例都使用边长 0.02 m 的立方体，24×24×24 个六面体，共 13,824 个单元。
左面 400 K，右面 300 K，其余外表面绝热。初始温度为 300 K，左面初始即为
400 K。全部节点与积分点使用同一编号和坐标，`mesh.py` 只生成网格及几何集合。

- 稳态和普通瞬态使用一个连续区域，共 15,625 个温度自由度。
  导热系数 10 W/(m K)，密度 1000 kg/m³，比热 100 J/(kg K)，
  均匀体热源 10⁶ W/m³。
- 界面算例在 x=0.01 m 处分成两个独立区域，共 16,250 个温度自由度。
  每侧界面含 576 个面和 625 个节点；两侧节点不合并。热端区域材料同上，
  冷端区域导热系数 20 W/(m K)，密度 2000 kg/m³，比热 200 J/(kg K)，
  体热源 2×10⁶ W/m³。面到面界面导热系数为 1000 W/(m² K)。
- 两个瞬态算例均采用固定 0.1 s 时间步，计算到 2 s，共 20 步。
  一阶热容采用节点集总，两个程序均采用隐式后向欧拉时间离散。

Fuelsim 使用 Release、GCC 14.3、链接时优化和 MUMPS 直接求解器；Abaqus
使用其默认直接求解器。所有生产计算单进程、单线程；Linux 使用
`taskset -c 0`，Windows 在启动作业前设置 affinity mask=1 并指定 `cpus=1`。
四个数值库线程环境变量均设为 1，没有并发运行性能样本。
具体编译链接参数见 `build_provenance.json`，运行环境与输入指纹见
`timing_provenance.json`。

生产可执行文件来自独立源码构建；170 个 `src/`、`include/`、`elements/`
受追踪文件均与 `e9516dd` 逐字节一致，未混入工作区其他未提交的求解器修改。

## 精度和工作量检查

单独的精度输入保存完整场；计时输入仅关闭输出，`run.py` 在运行前逐字节
核对两种输入的物理、边界、执行器和求解器部分相同。不在脚本中生成或修改
生产输入卡。原生输入除输出请求外也保持一致。

| 算例 | 比较时刻数 | 每时刻节点数 | 每时刻积分点数 | 最大逐点相对误差 |
|---|---:|---:|---:|---:|
| 稳态导热 | 1 | 15,625 | 110,592 | 0.0001366% |
| 瞬态导热 | 20 | 15,625 | 110,592 | 0.0034722% |
| 瞬态界面 | 20 | 16,250 | 110,592 | 0.0042339% |

逐时刻比较所有节点温度、温升、热反力及全部积分点三个热流分量。
沿用相对二范数、峰值及逐点误差小于 0.5% 的门槛；理论零横向热流按
绝对 10⁻⁷ W/m² 检查，零热反力按绝对 10⁻⁷ W 检查。不使用相对误差分母下限。
参考保留原生输出精度。全部场均通过，具体指标见 `validate_summary.json`。

每个稳态运行均完成一步、一次迭代；每个瞬态运行均完成 20 步、20 次迭代，
没有缩小时间步重试。预热及三次正式样本的迭代、残量和切线计算次数一致。
Abaqus 输入警告包括默认绝对零度及对左边界节点覆盖初始温度；初始值与
Fuelsim 的固定温度边界一致，没有分析阶段数值警告。

## 已确认的优化位置

正式计时后，另外启用 PETSc 性能事件日志进行诊断，诊断时间不计入上述统计。
两个瞬态算例都记录了 20 次符号分解和 20 次数值分解；Abaqus 原生分析摘要
均记录一次矩阵分解、20 次方程求解。
Fuelsim 的数值分解累计约为普通瞬态 3.76 s、界面瞬态 4.38 s；符号分解
分别约 1.97 s、1.95 s。原始记录仅保存在本地 `diagnosis/`，这些事件可能与更上层
事件嵌套，不能把整个日志中的耗时直接相加。

本组材料、几何、步长和界面导热系数固定，后续可研究在确实不改变矩阵时
复用装配及分解结果。此次只建立基准，没有修改生产算法，也没有提前承诺
复用后的加速幅度。该结论不能推广到温度相关物性、移动界面或自适应步长。

本轮仅代表线性 DC3D8、匹配平面界面和上述规模。横截面载荷均匀，解主要
沿 x 变化，但两个求解器都实际装配并求解完整三维网格。没有据此宣称
DCAX4/DCAX8/DC3D20、非匹配曲面或任意工程规模具有同样的速度优势。

## 重现

仓库只提交完整输入卡、生成网格和运行计算的脚本、结果摘要及复现说明。生成的网格、
完整原生参考场和原始日志仅保存在本地，并由本目录 `.gitignore` 排除。
新检出目录首先生成两个程序使用的相同网格；此脚本只生成几何，不生成或修改
材料、边界条件、求解器等生产问题定义：

```sh
python verification/thermal/performance/mesh.py
```

本地仍有 `references/` 完整参考时，可以离线检查精度，无需启动 Abaqus：

```sh
env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 NUMEXPR_NUM_THREADS=1 \
  /home/cooper/miniforge/bin/python3 verification/thermal/performance/run.py \
  --fuelsim /absolute/path/to/fuelsim --work /tmp/thermal-perf-check --mode check
```

新检出目录没有完整原生参考，须使用 Windows Abaqus 2025 重新进行精度验证，
再开展重复计时。参考提取、比较和计时结果均写入指定工作目录：

```sh
python verification/thermal/performance/run.py --fuelsim /absolute/path/to/fuelsim \
  --work /tmp/thermal-perf --mode validate
python verification/thermal/performance/run.py --fuelsim /absolute/path/to/fuelsim \
  --work /tmp/thermal-perf --mode timing
python verification/thermal/performance/summarize.py /tmp/thermal-perf
```

本地 `samples/` 保留各轮原始生产日志、原生分析记录和外部计时；编号 0 为
预热，编号 1—3 为正式样本。本地 `references/` 保存完整原生字段和分析记录，
这些目录不提交。提交的 `timing_summary.json` 保留每个样本的计时、迭代次数和
矩阵分解次数，`validate_summary.json` 保留逐字段误差，`summary.json` 汇总比较结果。
这些是手动性能资料，不加入日常 CTest，也不在日常测试中启动 Abaqus。
