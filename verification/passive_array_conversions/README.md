# 双精度与自动微分之间的数组转换清理

日期：2026-09-16。比较基线：`def7668`。

## 搜索与修改范围

检查 `elements/src`、`elements/include`、`src` 和 `include` 中的自动微分类型、
数组转换辅助函数、无导数状态构造、双精度结果回写和残量提取调用。
自动微分类型 `adlite::Scalar` 同时保存数值和导数；固定形函数权重本身没有导数，
可以用双精度数组直接乘仍然携带导数的节点坐标。

| 位置 | 原来的中间转换 | 当前处理 |
|---|---|---|
| `quad4_face.cpp` | 固定次表面形函数转成四个自动微分标量 | 插值、摩擦相对位置和力分配直接使用双精度权重 |
| `quad8_face.cpp` | 固定形函数、温度权重和面局部导数转成自动微分数组 | 使用具体的双精度权重插值入口，删除数组转换辅助函数 |
| `c3d8t.cpp` | 双精度残量转成自动微分数组，最后重新取数值；已经提取导数的积分点残量仍累加导数 | 装配接口直接返回双精度残量，积分点导数只进入单元导数矩阵 |
| `c3d8rt.cpp` | 有限应变双精度残量整批转入自动微分数组，小应变数值贡献也用自动微分数组累加 | 两种装配接口均直接使用双精度残量 |
| `material.cpp` | 轴对称双精度张量和旋转值转成自动微分对象，旋转后再取数值 | 数值旋转函数直接使用双精度四分量计算 |

保留的转换有明确用途：

- 当前节点状态需要建立导数，已接受的历史状态需要作为常量参与同一自动微分表达式。
- 材料函数注册表以 `adlite::Scalar` 为具体入口；数值调用仍需遵守该接口。
- 有限滑移投影的主表面权重包含几何导数，不能统一改为双精度。
  八节点小滑移投影共用该结果结构，只在写入最终结果时保存常量权重，插值不再创建临时自动微分权重数组。
- C3D8T 小应变纯残量分支仍使用原有自动微分算术，在该分支出口提取一次数值。

未增加模板或通用标量层，未改变积分规则、物理输入、收敛判据和误差门槛。

## 验证方法

局部测试覆盖四节点与八节点接触面、C3D8T/C3D8RT 残量与导数矩阵，
并增加非坐标轴方向的轴对称张量旋转对照和迹不变性检查。
完整回归使用 `ctest --test-dir build -j8 --output-on-failure`。

生产输出对照使用原样复制的已有输入卡与网格，分别运行基线和修改后的
`fuelsim -i <case.fsi>`，检查完整时间序列的节点场、积分点场、数组形状以及 NaN 位置。
例题包括 B3.7 的八节点体单元多接触摩擦、B5.17 的 C3D8T 有限应变耦合材料、
B5.37 的 C3D8RT 有限应变耦合材料、B7.1 的 CAX4T 有限应变耦合材料、
B9.4 的 CAX4RT 有限应变耦合材料，以及 C3D20RT 有限应变接触首增量。

接触例题性能比较沿用已有脚本，固定 CPU 0、一个求解进程和单线程，
保持原始输入卡的 MUMPS 直接求解器设置，预热一次后交替运行五次：

```bash
python benchmarks/run_c3d20rt_comparison.py \
  /path/to/def7668/fuelsim build/fuelsim /tmp/passive-array-timing \
  --case finite_contact_first_increment --cpu 0 --repeats 5
```

## 结果

六个生产例题共比较 2880 个时间或场数组，全部有限数值逐项相同，数组形状、
有限数值位置和 NaN 位置一致。各例题的时间步、非线性迭代、残量和导数矩阵计算次数相同。
见[逐字段比较](field-comparison.csv)和[求解次数](solver-counts.csv)。

接触首增量例题的外部总耗时中位数为 4.224583 → 4.188972 秒，减少约 0.84%。
本批次差异较小，不据此声称稳定加速，也不将此比例推广到其他型号或例题。
本次确定减少的是临时自动微分数组构造、数值转写，以及 C3D8T 中已经提取到导数矩阵后的重复导数累加。
见[逐次计时](runs.csv)、[输入校验值](inputs.sha256)和[二进制校验值](executables.txt)。

完整 Release 构建成功，326 项统一回归全部通过，总耗时 152.36 秒。

```bash
env OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1 \
  taskset -c 0-7 ctest --test-dir build -j8 --output-on-failure
```
