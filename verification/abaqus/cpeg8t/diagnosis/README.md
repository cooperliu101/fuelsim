## 小应变蠕变：已确定时间积分方法不同

本例 Norton 指数为 1。令三维应力偏量为 `s`，蠕变张量增量应满足下列对应关系：

```text
前向 Euler：Δε_creep = 1.5 × 1e-7 × Δt × s_old
后向 Euler：Δε_creep = 1.5 × 1e-7 × Δt × s_new
```

`analyze.py` 在每个时间步、每个活跃材料点检查原生蠕变张量的全部四个输出分量，
并先把原生工程剪应变转换为张量剪应变。结果如下：

| 材料与阶段 | 原生识别结果 |
|---|---|
| 小应变纯蠕变，全部 12 个增量 | 前向 Euler |
| 小应变耦合材料，加载阶段与反向塑性阶段 | 后向 Euler，同时存在正的等效塑性应变增量 |
| 小应变耦合材料，保持阶段与卸载第一个增量 | 前向 Euler，等效塑性应变没有增加 |
| 对应有限应变的纯蠕变与耦合材料 | 全部使用后向 Euler |

小应变和有限应变的已识别公式最大张量残差分别为 `9.49e-20` 和 `1.08e-19`。
这项检查的绝对门槛为 `1e-12`，只用于识别原生更新公式，不替代原有比较门槛。

例如，小应变纯蠕变的第一个 0.25 s 增量中，原生初始应力为零，因此前向 Euler
给出零蠕变增量；Fuelsim 的后向 Euler 在步末应力下得到非零增量。这个差异不能
通过更严格的牛顿收敛标准消除。卸载时，两种方法还可能使用不同的流动方向。

这一结果与 [Abaqus 蠕变理论说明](https://docs.software.vt.edu/abaqusv2025/English/SIMACAETHERefMap/simathe-c-ratedepplast.htm)
一致：几何非线性或同时激活率无关塑性时采用隐式积分。这里只对所列输入和状态
完成了逐点识别，没有推广到其他材料指数、载荷或时间步。

`creep_implicit_request.inp` 保持原题物理输入，仅尝试在原生分析步中写入
`CREEP=IMPLICIT`。Abaqus 2025 输入处理器明确拒绝该值；原始错误摘录保存在
`creep_implicit_parser_error.txt`。因此不能用这个未支持的关键字把参考改成后向 Euler。
本诊断也没有把小应变参考改为有限应变，或给生产材料增加显式积分分支。

## 非均匀接触：间隙平均与法向定义均不同

五个新增原生探测都固定全部场节点的位移、温度和截面量，从而避免结构求解误差
混入接触算子识别。弹性模量、接触罚刚度、厚度与原题一致；直接读取从侧
`CNORMF`，即原生法向接触力向量。

`contact_modes.inp` 分别施加均匀、线性和二次间隙变化。
`contact_operator.inp` 再对从侧两个角点及一个边中点分别施加正、负法向扰动，
由中心差分测得三节点接触力导数矩阵。扰动为 `1e-7 m`，基准过闭合量为 `1e-4 m`。
`contact_operator_shallow.inp` 将二者分别减至 `1e-10 m` 和 `1e-8 m`，以检查
深度过闭合产生的几何项是否是主要差异来源。

浅过闭合探测的矩阵除以 `罚刚度 × 初始厚度 × 边长的一半 = 1e6 N/m` 后约为：

```text
Abaqus：                         逐点罚力的精确积分：
 0.181730  -0.042506  0.194109      0.266667  -0.066667  0.133333
-0.042506   0.181730  0.194109     -0.066667   0.266667  0.133333
 0.194109   0.194109  0.945116      0.133333   0.133333  1.066667
```

矩阵相对 Frobenius 范数差约为 **18.22%**，最大逐项相对差约为 **45.58%**。
两者对均匀间隙的响应一致，但对非均匀间隙的响应不同。增加逐点积分的精度不能
消除这种算子差异。此处没有用测得的矩阵系数修改生产实现。

进一步把主侧宽度扩大到从侧的 1.5 倍，`contact_operator_wide` 得到相同矩阵，
说明上述差异不是两侧端点恰好重合产生的投影截断误差。

从原生 `COPEN`，即接触间隙输出，独立测得间隙平均矩阵 `A` 后，再用均匀载荷
确定正权重 `W`，可按 `Aᵀ diag(W) A` 重构上面的原生力导数矩阵。
归一化矩阵的最大重构残差约为 **9.9e-13**。这里非均匀力导数没有参与权重识别，
因此是对平均约束结构的独立检验。测得的平直单边线性化系数约为：

```text
A = [ 0.587612  -0.085095  0.497483
     -0.085095   0.587612  0.497483
      0.083581   0.083581  0.832839 ]
W = [0.495510, 0.495510, 1.008980]
```

这些系数尚不能用于曲边、跨从侧单元邻域或变形后的接触。它们只识别了当前几何下
的离散算子，没有确定连续平均权函数及其几何更新，不能作为生产代码中的固定常数。

`contact_primary_tilt.inp` 只倾斜主侧表面，与 `contact_modes` 中只倾斜从侧的
线性间隙探测相互印证。三个从侧节点的接触力均满足：

| 几何设置 | 原生 `Fx/Fy` | 使用主侧法向时的预测 |
|---|---:|---:|
| 主侧水平，从侧斜率 0.005 | -0.005 | 0 |
| 从侧水平，主侧斜率 0.005 | 约 0 | -0.005 |

这与 [Abaqus 面到面接触说明](https://docs.software.vt.edu/abaqusv2025/English/SIMACAEITNRefMap/simaitn-c-contactpairform.htm)
中的从侧邻域平均约束和从侧平均法向一致。当前 Fuelsim 的实现按积分点间隙施加
罚力，方向取主侧投影处法向，因此 `sections_contact` 的差异不只是积分区间问题。
现有证据尚未识别 Abaqus 的完整平均权函数，不能声称已经恢复其全部接触算法。

## 跨单元滑移：合力与力矩正确，节点分配不同

在 `contact_cycle` 的 `t=1 s`，从侧覆盖主侧分界两侧各 0.005 m，压力为
100000 Pa。主侧两个单元的位移、截面量和温升均为零；脚本确认全部材料点应力
为零，因此主侧节点反力 `RF` 可直接作为接触节点力参考。

| 主侧节点 | 分段解析积分，N | 原生 RF，N |
|---|---:|---:|
| 4 | -4.166666667 | -4.110544159 |
| 7 | 20.833333333 | 20.608843301 |
| 3 | 66.666666667 | 67.003401715 |
| 13 | 20.833333333 | 20.608843301 |
| 10 | -4.166666667 | -4.110544159 |

原生合力仍为 100 N，关于界面中心的力矩仍为零，最大节点差为 0.336735 N。
全路径最大逐点相对差仍约为 2.05%，原有 0.5% 门槛没有通过。

还发现原生主侧 `CNORMF` 在节点 4、10 输出零，而 `RF` 非零；不能直接用这些
`CNORMF` 值替换节点反力，或删除二次形函数导致的负节点反力。这里仅记录该原生
输出差异，不推测其内部输出处理方式。现有生产比较一直使用全部主侧 `RF`，
因此失败不是这项输出替换造成的。

## 后续实现需要解决的问题

小应变蠕变比较必须继续区分材料方程正确性和时间离散方法一致性。Fuelsim 保持
后向 Euler 数值契约；原题保留失败状态。若增加时间步收敛比较，应在相同物理
时间比较完整历史，同时保留原粗时间步结果，不删除最初的零蠕变参考量。

要进一步对齐非均匀接触，需要先确定从侧平均约束的权函数、支持范围，以及主侧
形函数如何参与力的分配，再形成相应残量和几何切线。仅把当前法向替换为从侧
法向不能解决间隙平均差异。实施前还需要明确：逐点罚力的解析节点分布与 Abaqus
的平均约束在粗网格上不同，不能把二者当作同一种离散方法要求同时逐节点相等。

## 复现方式

在已安装 NumPy 的 Python 环境中运行：

```bash
python3 verification/abaqus/cpeg8t/diagnosis/analyze.py
```

脚本校验参考文件，检查上述恒等式并写出 `diagnosis.json`。它不调用生产求解器，
属于原生算子诊断，不能替代生产例题。原生重算在本目录中执行：

```powershell
..\run.ps1 -SourceDirectory $PWD -JobName contact_operator_shallow
```

其余有效任务为 `contact_modes`、`contact_operator`、`contact_operator_wide` 和 `contact_primary_tilt`。
`creep_implicit_request` 是预期被输入处理器拒绝的语法探测，不是可通过的例题。
新增原生输入、字段及错误摘录由本目录 `reference.sha256` 固定；父目录原始参考保持不变。

三个生产例题可从仓库根目录重新运行。下面的前两个命令预期返回 1；第三个命令
返回 0 只表示分段解析积分检查通过，原生比较的失败仍记录在输出报告中。
Python 环境需要 NumPy 和 netCDF4，求解器路径应指向待检查的实际构建：

```bash
python3 verification/abaqus/cpeg8t/check_extended.py --case sections_contact \
  --executable "$PWD/build/fuelsim" --work /tmp/cpeg-diagnosis-sections
python3 verification/abaqus/cpeg8t/check_inelastic.py --require-native \
  --executable "$PWD/build/fuelsim" --work /tmp/cpeg-diagnosis-inelastic
python3 verification/abaqus/cpeg8t/check_contact_cycle.py --require-distribution \
  --executable "$PWD/build/fuelsim" --work /tmp/cpeg-diagnosis-cycle
```
