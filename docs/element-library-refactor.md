# 单元库按型号整理与默认 Quad4 删除

本次整理以 `0d0454b` 为基线。八种体单元分别以 `cax4t`、`cax4rt`、`cax8t`、
`cax8rt`、`c3d8t`、`c3d8rt`、`c3d20t`、`c3d20rt` 命名公共头文件、实现文件
和测试文件。文件与调用边界见 [单元库说明](../elements/README.md)。

## 实现边界

- C3D8T 的选择性体积处理、完整积分装配与 C3D8RT 的均匀应变、单点材料积分、
  沙漏装配分属两个型号文件；共用几何、材料增量更新、张量旋转及矩阵运算独立维护。
- CAX8T/CAX8RT 与 C3D20T/C3D20RT 分别在型号入口选择积分阶数，同拓扑的
  形函数与积分点装配共用；入口检查几何包含的材料积分点数量。
- 轴对称与三维边界积分从体单元文件移出，接触接口按线段或表面拓扑拆分。
- `src/detail/` 是库的私有包含目录，公共头文件不引用它。单元库不反向依赖
  fuelsim 主体。主体负责型号选择、全局装配、候选搜索、时间推进与状态事务。
- 请求使用具体类型和 `ElementRequest`，没有新增模板、对象工厂或旧接口别名。

## 删除范围与测试覆盖

默认轴对称 `quad4` 的枚举、输入选择、体单元函数、Taylor/Rashid 增量算法及
旧热算子诊断已经删除。四节点几何映射、形函数和四节点三维表面仍被保留型号使用。

删除的局部测试为旧 Quad4 的稳态 Jacobian、Taylor/Rashid 运动学、参考构形
一致热容矩阵以及对应的瞬态耦合单元 Jacobian 检查。这些断言不能直接用于
CAX4T。保留的 CAX4T/CAX4RT 专用测试覆盖各自热容、热源、材料历史、有限应变、
塑性与蠕变耦合导数；B7、B9、B13、B15 等生产验证继续使用既定参考和误差门槛。
材料点更新、客观历史旋转、全局事务、边界及接触检查继续保留。

原有混合测试的共用断言编译在 `elements/tests/support/`，由各型号测试分别调用。
独立 CTest 包含八个型号测试和一个共用轴对称边界、接触测试。

## 输入迁移

每个 `[Regions]` 子区域必须显式给出 `element`，缺失或填写 `quad4` 都会报错。
四节点轴对称旧默认输入改为显式 CAX4T；二十节点三维网格改为显式 C3D20T，
不再使用 C3D8T 名称隐式决定二十节点公式。显式三维型号与网格节点数不匹配时，
在问题构造阶段报错。

所有修改后的 `.fsi` 输入卡以完整文本保存，不通过测试程序或脚本在运行时生成。
输入解析测试覆盖旧型号、缺失型号及型号与网格不匹配的拒绝行为。

## 验证记录

使用 GCC 14.3、Release、ADlite 0.2.3，并开启编译警告作为错误。
单元库仅发现 ADlite，不需要 PETSc 或 Exodus 即可独立构建。

C3D8T/C3D8RT 与 C3D20T/C3D20RT 分开执行后，合并的数值指标与基线逐字一致。
CAX8T/CAX8RT 的节点和积分点探测输出一致；拆分后各自报告最大方向导数误差，
因此多出一个型号自身的最大误差值。此比较只约束现有测试状态及打印精度，
不声称所有输入逐位一致，也不用于证明旧 Quad4 与 CAX4T 数值等价。

共享节点的 CAX4T 装配方向导数检查保留原有 `2e-7` 归一化误差门槛。
原先 `1e-5` 扰动下，大初始热应力残量相减导致的误差为 `2.69e-7`；
改用 `1e-3` 和 `3e-3` 两个扰动尺度后，三个场的最大误差分别为
`4.66e-9` 和 `1.20e-9`。检查点测试改为在 CAX4T 与 CAX4RT 之间切换，
继续验证不同型号的检查点签名不同。

独立构建的 9/9 个测试通过。主构建通过，统一入口 `ctest --test-dir build -j4 --output-on-failure` 的 277/277 个测试通过。
外部求解器对比使用仓库中已有的 Abaqus/MOOSE 参考数据，没有修改参考值或
误差门槛，也没有重新生成外部参考或进行性能提升评估。

## 后续公共类型边界整理

在 `4a2abb5` 基础上统一四个型号族类型头文件：各自承载拓扑几何、局部数组和
输入输出。轴对称与三维公共类型只保留跨拓扑的应力、材料历史和转动数据。
四节点专用的 `Local*` 类型改为 `Cax4Local*`，旧公共几何头文件删除。

区域材料和型号选择由主体的 `element_region_data.hpp` 持有；单元计算直接使用
型号族 `Input`，不再定义重复的内部材料载荷结构。沙漏能量接口也采用相同输入。
主体原有的 C3D8T 零沙漏能量分支保留在主体型号选择处，C3D8RT 专用函数只计算
该型号的能量。八节点运动学诊断接口独立放在 `c3d8_kinematics.hpp`，内部计算
辅助结构继续放在 `src/detail/`。

本次不修改数值公式、输入卡、外部参考值或验收误差门槛。

验证结果：单元库独立构建及 9/9 项测试通过，主体构建及统一入口的 277/277 项
测试通过。七个类型头文件、材料头文件、八个型号头文件和运动学诊断头文件
共 17 个公共头文件均通过单独包含的 C++17 编译检查，仅提供 ADlite 包含路径。

## C3D8 运动学接口收回库内部

在 `db1f3ef` 基础上删除公共 `c3d8_kinematics.hpp`，将结构和函数声明并入
`src/detail/hex8_geometry.hpp`。型号头文件分别提供整单元诊断入口
`diagnose_c3d8t`、`diagnose_c3d8rt`，输出不携带自动微分类型。
主体、局部验证与手动基准全部改用这两个型号入口，没有保留旧接口别名。

主体能量诊断仍使用相同的新旧体积和增量转动，热流验证仍使用相同的点梯度、
体积平均梯度和型号温度规则。诊断独立于残量、Jacobian 和材料更新请求；没有
改变物理公式、输入卡、外部参考或误差门槛。

新增局部检查覆盖八点与一点的输出数量、新旧构形体积区分、相对已接受构形的
刚体增量转动、当前坐标线性温度场的梯度重建、型号温度规则、输入不变性，以及
当前、已接受和中间构形非法时的异常行为。

验证结果：主体构建成功，统一回归 `ctest --test-dir build -j4 --output-on-failure`
的 277/277 项测试通过；单元库独立构建及 9/9 项测试通过。C3D8T、C3D8RT 和
共用类型三个公共头文件通过仅依赖 C++17 与 ADlite 的单独包含编译检查。

## 私有实现按职责整理

在 `9fe2806` 基础上统一 `detail` 文件名称：型号族使用 `cax4`、`cax8`、`c3d8`、
`c3d20` 前缀，几何、运动学、装配与诊断按职责分别维护。当前结构见单元库 README。
历史记录中的 `hex8_geometry.hpp` 等名称对应拆分前的文件。

C3D20 原共用装配中的参考几何、构形运动学和热几何分别抽出；CAX8 抽出参考几何，
其小型运动学仍留在共用装配。三维本构切线与材料上下文从运动学移入
`cartesian_material`，普通双精度矩阵乘法和张量旋转合并到已有公共算法。
保留原有乘加顺序、普通双精度残量路径和自动微分路径，没有扩大播种宽度。

轴对称线段合法性检查与自动微分数据转换分开。只有 CAX4T 使用的四节点插值
留在型号实现中，原来未使用的自动微分插值重载删除，不为文件配对增加空头文件。
输入卡、外部参考数据、误差门槛和测试集合不变；验证矩阵仅更新当前源码路径。

拆分前后九个独立局部测试的完整标准输出与错误输出逐字一致。这一比较仅覆盖
现有局部测试状态和输出精度，不代表任意输入逐位一致，也不构成性能结论。

验证结果：最终主体构建成功，统一入口 `ctest --test-dir build -j4 --output-on-failure`
的 277/277 项测试通过；独立单元库构建及 9/9 项测试通过，最终局部测试输出仍
逐字匹配整理前记录。当前保留的 14 个私有头文件均通过仅依赖 C++17、ADlite
和单元库包含目录的单独包含编译检查。

## 私有实现功能边界复核

在 `7a6642e` 基础上逐文件核对定义、声明与调用方，修正仍然混合的职责。
CAX8 的运动学、当前力学梯度、中间构形热梯度和线性源项几何移入
`cax8_kinematics`；C3D20 重复的温度形函数构形映射统一由其运动学文件提供。
CAX8、C3D20 共用装配只接收 `Input` 与 `ElementRequest`，请求处理从两个型号
入口收回共用装配，C3D20 不再对其他文件暴露四个仅供自身调用的计算函数。

私有命名空间按实际共享范围统一；两节点轴对称边界和接触的局部数组转换改名为
`line2_rz_local_system.hpp`。C3D8 诊断复用几何文件已有的节点与积分点映射，
只供参考几何使用的积分常数收回实现文件。

新增源码边界检查，并用临时副本验证它能拒绝几何文件包含材料实现、公共头文件
包含私有实现，以及运动学代码引入材料上下文。该检查只约束直接包含关系和
显式源码模式，不是完整的 C++ 语义分析。全部 28 个私有文件的职责和保留边界见
[单元库私有实现职责核对](element-detail-boundaries.md)。

验证结果：最终独立单元库构建及 10/10 项测试通过，九个原有局部测试的标准输出
与本次整理前逐字一致，错误输出为空；15 个私有头文件通过单独包含编译检查。
最终主体构建及统一入口的 278/278 项测试通过。外部对标继续使用已有参考数据，
没有修改物理输入、参考值或误差门槛，也没有进行性能提升评估。
