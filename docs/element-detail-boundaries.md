# 单元库私有实现职责核对

本次核对以 `7a6642e` 为基线，检查 `elements/src/detail` 的函数定义、私有声明、
包含关系与实际调用方。代码分配按计算职责和共享范围确定，不要求所有型号族
具有数量相同的文件。

## 统一分配规则

参考形函数与参考积分数据归几何；随状态变化的构形、应变、转动、形函数梯度和
积分测度归运动学；材料状态与本构切线归材料；场插值、物理项积分及局部导数矩阵
的闭式节点链归装配。几何导数与导热系数、应力、热容等物理量组合后，已经属于
装配职责，不能只因表达式中出现逆矩阵或形函数就移回运动学。

私有声明只暴露跨文件使用的函数。公共几何和材料接口的实现可以位于相应职责的
私有实现文件中，但声明仍以公共头文件为准。公共头文件和 fuelsim 主体不能包含
单元库的私有头文件。私有文件间允许的直接包含关系由
`elements/tests/detail_boundaries.cmake` 检查；新文件必须明确分类后才能通过。

CAX4T/CAX4RT 和 C3D8T/C3D8RT 的选择性体积处理、均匀应变和沙漏控制按型号
维护，不能为了文件数量对称而建立空的共用装配层。CAX8 和 C3D20 两组型号实际
共用积分点算法，因此统一共用装配入口。

C3D20 的普通双精度残量路径与 ADlite 路径有不同计算用途，继续分别实现，
不引入标量模板。构形合法性检查、材料历史事务、自动微分播种宽度、输入卡、
外部参考值和误差门槛保持原有约定。

## 验证结果

最终源码的单元库独立构建通过，10/10 项测试通过；其中九个原有 C++ 局部测试的
标准输出与整理前逐字一致，错误输出均为空。这只覆盖已有测试状态与输出精度，
不代表所有输入逐位一致。15 个私有头文件均通过仅提供单元库与 ADlite 包含目录
的 C++17 单独包含编译检查。

最终主体构建通过，统一入口 `ctest --test-dir build -j4 --output-on-failure`
的 278/278 项测试通过。源码边界检查也通过临时副本中的三类违规反向验证。
外部求解器比较使用仓库已有参考数据，没有重新运行 Abaqus 或 MOOSE，也没有
进行性能提升评估。
